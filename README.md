# ЗагрузкаДокументовКонтурЛогистика

Внешняя обработка для 1С:Предприятия, которая загружает документы из сервиса
**Контур.Диадок** в подсистему **Контур.Логистика** по известным идентификаторам
(`BoxId`, `MessageId`, `EntityId`).

Обработка полезна, когда документ нужно «дотянуть» в базу вручную: например,
письмо пришло, но не было обработано регламентным заданием, или требуется
повторно загрузить титул в конкретную базу.

## Состав

Проект EDT с природой `V8ExternalObjectsNature` (внешние объекты), базовая
конфигурация — `ВЫГРУЗКАКЛ1` (Конфигурация «КонтурЛогистика», ред. 1.22.5).

```
ЗагрузкаДокументовКонтурЛогистика/
├── .project                        проект EDT
├── DT-INF/PROJECT.PMF              манифест: Runtime-Version 8.3.27, Base-Project ВЫГРУЗКАКЛ1
├── .settings/                      настройки EDT (v8codestyle и пр.)
└── src/ExternalDataProcessors/
    └── КонтурЛогистика_ЗагрузкаДокументаИзДиадок/
        ├── КонтурЛогистика_ЗагрузкаДокументаИзДиадок.mdo
        └── Forms/Форма/
            ├── Form.form          управляемая форма
            └── Module.bsl         вся логика загрузки (~1100 строк)
```

Внешняя обработка: `КонтурЛогистика_ЗагрузкаДокументаИзДиадок`
(синоним — «Загрузка документа из Диадок (по идентификаторам)»).

## Требования

| Компонент | Версия / примечание |
| --- | --- |
| 1С:Предприятие | 8.3.27 (Runtime-Version проекта) |
| Конфигурация | «КонтурЛогистика» (базовый проект EDT `ВЫГРУЗКАКЛ1`), совместимость 8.3.26 |
| Режим | управляемое приложение, управляемые блокировки |
| БСП | общий модуль `ОбработкаОшибок` |
| Доступ | настроенное подключение к API Диадок (ящик `BoxId` должен быть доступен в базе) |

## Как пользоваться

1. Открыть обработку (внешний отчёт/обработка) в нужной базе.
2. Заполнить идентификаторы документа в Диадок:
   * **BoxId** — идентификатор ящика организации;
   * **MessageId** (LetterId) — идентификатор сообщения;
   * **EntityId** (DocumentId) — идентификатор документа (сущности).
3. Нажать **«Загрузить документ»**.
4. Результат отображается в поле **«Результат»** и в служебных сообщениях:
   создан ли прикладной документ, создан ли только файл обмена, найдена ли
   подпись и прошла ли она проверку.
5. Кнопка **«Открыть файл обмена»** открывает созданный/найденный элемент
   справочника `КонтурЛогистика_ФайлыОбмена`.

## Что делает обработка

Загрузка выполняется на сервере (`ЗагрузитьДокументИзДиадокНаСервере`):

1. **Проверка дубля.** Ищет файл обмена по паре `MessageId` + `EntityId`
   (`Справочники.КонтурЛогистика_ФайлыОбмена.НайтиФайлОбмена`). Если файл уже
   есть — повторно ничего не скачивает, а доводит обработку до конца
   (создаёт прикладной документ, если прошлый вызов упал раньше).
2. **Метаданные документа.** Через `КонтурЛогистика_API_Диадок.АПИ_GetDocument`
   получает карточку документа и проверяет наличие `FileName`.
3. **Тип и версия.** Тип определяется по имени файла
   (`Перечисления.КонтурЛогистика_ТипыЛогистическихДокументов.ОпределитьТипДокументаПоFileName`),
   версия формата — из `DocumentInfo.FullVersion.Version`. Для ЭР, СР и ПЭ
   версия формата сверяется с текущей версией СТД в конфигурации
   (`Документы.КонтурЛогистика_ЭкспедиторскаяРасписка`, `..._СкладскаяРасписка`,
   `..._ПЭ_Титул1`); при несовпадении загрузка прерывается с понятной ошибкой.
4. **Контент.** Скачивает содержимое сущности (`АПИ_GetEntityContent`),
   определяет кодировку XML (UTF-8 / UTF-16 / пролог `encoding`) и разбирает
   XML в XDTO (`КонтурЛогистика_КонструкторыXDTO.ПолучитьXDTOпоXML`), забирая
   `ВерсФорм` и `ВерсПрог`. GUID берётся из хвоста имени файла.
5. **Стороны.** Отправитель и получатель определяются по имени файла
   (`ОтправительИПолучательПоFileName`).
6. **Подпись и МЧД.** По документообороту (`Диадок_АПИ_GetDocflows`) находится
   ветка титула, из неё — `EntityId` подписи (приоритет `CadesT` над `Cms`),
   скачивается сама подпись, данные подписанта и DER-сертификат. Машиночитаемая
   доверенность: идентификатор, статус приложенности, статус проверки, ошибки;
   входящая МЧД загружается в справочник `КонтурЛогистика_МЧД` и, если она
   «чужая», её статус проверки актуализируется.
7. **Шаблонные документы.** Если `Document.Origin.MessageType = "Template"`,
   заполняются `ШаблонОснование`, `ОтправительШаблона` и `EditingSettingId`.
8. **Запись файла обмена.** Создаётся элемент `КонтурЛогистика_ФайлыОбмена`:
   версии, GUID, сжатый XML (`ХранилищеЗначения` + `СжатиеДанных(9)`),
   `DocumentId`, `MessageID`, тип документа, имя файла, стороны, дата
   формирования, `PacketId`, признак тестового документа, `CustomData`,
   состояние `Получен`, канал транспорта `Диадок`.
   Запись выполняется в транзакции под исключительной блокировкой справочника,
   с повторной проверкой дубля — параллельный вызов не создаст второй файл.
9. **Прикладной документ.** Вызывается
   `КонтурЛогистика_ОбработкаДокументовСервер.СоздатьТитулыПоЗагруженнымФайламОбмена`,
   который создаёт титул/документ по загруженному файлу обмена.
10. **Ошибка подписи.** Если подпись не прошла проверку, в
    `РегистрСведений.КонтурЛогистика_СтатусыТитулов` добавляется запись со
    статусом `Ошибка` и типом ошибки `ОшибкаПодписи` (код и описание —
    из статуса сертификата), файл обмена переводится в состояние
    `ОшибкаОтправки`. Записи регистра не удаляются: новая запись пишется с
    периодом «максимальный + 1».

Все исключения перехватываются: пользователю показывается текст ошибки,
подробности пишутся в журнал регистрации с именем события
`КонтурЛогистика_ОбщегоНазначенияКлиентСервер.ИмяСобытияЖурналаРегистрации()`.

## Используемые объекты конфигурации

| Объект | Назначение |
| --- | --- |
| `Справочник.КонтурЛогистика_ФайлыОбмена` | файл обмена: XML, подпись, сертификат, состояние, связь с документом |
| `Справочник.КонтурЛогистика_МЧД` | машиночитаемые доверенности, их статусы и ошибки проверки |
| `Справочник.КонтурЛогистика_ОрганизацииДиадок` | организация-отправитель шаблона |
| `Перечисление.КонтурЛогистика_ТипыЛогистическихДокументов` | тип документа по имени файла, признаки ЭР/СР/ПЭ, ответный титул |
| `Перечисление.КонтурЛогистика_СосотоянияФайловОбмена` | состояния файла обмена |
| `Перечисление.КонтурЛогистика_КаналыТранспорта` | канал `Диадок` |
| `Перечисление.КонтурЛогистика_СтатусыПодписи` | статус подписи из Диадок |
| `Перечисление.КонтурЛогистика_СтатусыТитулов`, `..._ТипыОшибокСтатусаТитула` | статус титула и тип ошибки |
| `РегистрСведений.КонтурЛогистика_СтатусыТитулов` | история статусов титулов |
| `Документ.КонтурЛогистика_ЭкспедиторскаяРасписка`, `..._СкладскаяРасписка`, `..._ПЭ_Титул1` | проверка поддерживаемой версии формата |

Общие модули: `КонтурЛогистика_API_Диадок`, `КонтурЛогистика_КонструкторыXDTO`,
`КонтурЛогистика_ОбработкаДокументовСервер`, `КонтурЛогистика_ОбщегоНазначенияСервер`,
`КонтурЛогистика_ОбщегоНазначенияКлиентСервер`,
`КонтурЛогистика_МашиночитаемыеДовернностиСервер`, `КонтурЛогистика_КриптографияСервер`,
`ОбработкаОшибок` (БСП).

## Сборка

Обработка собирается из проекта EDT в `.epf` штатным экспортом внешнего объекта
(или MCP-инструментом `build_external_objects` с указанием каталога выгрузки).
В репозитории хранятся только исходники проекта EDT — собранных `.epf` здесь нет.

## Ограничения

* Нужны корректные идентификаторы Диадок и доступ к соответствующему ящику.
* Загружаются только типы документов, поддержанные конфигурацией; версия формата
  должна совпадать с текущей версией СТД.
* Если титул 1 документа не был загружен ранее, файл обмена создастся, но
  прикладной документ не появится — обработка сообщит об этом.
* Отсутствие подписи в Диадоке не является ошибкой: файл загружается без подписи.
